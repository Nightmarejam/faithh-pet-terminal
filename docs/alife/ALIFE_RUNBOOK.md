## Architecture: The 8-Byte Genome

This is the fixed schema for validated experiments (0-7). Do not deviate.

```
[S0][S1][P0][P1][M0][A0][A1][R0]
 8 slots × 1 byte each = 8 bytes total
```

| Category | Slots | Key Ops | Cost |
|----------|-------|---------|------|
| SENSE | S0, S1 | ENERGY, THREAT, LIGHT, NEIGHBOR, DENSITY, SELF, GRADIENT, AGE | Free |
| PROCESS | P0, P1 | THRESHOLD, COMPARE, MEMORY_CMP, TREND, PREDICT, WEIGHT, AVG, INVERT | 0-4 energy |
| MEMORY | M0 | NONE, LAST1, LAST4, LAST8, BEST, WORST, PATTERN, HYBRID | 0-4 energy |
| ACT | A0, A1 | IDLE, MOVE, CONSUME, SHIELD, REPRODUCE, SIGNAL, TOXIN, FLEE | 0-5 energy |
| REGULATE | R0 | NONE, CONSERVE, BURST, CYCLE, LEARN, SUPPRESS, PRIORITIZE, ADAPTIVE | 0-4 energy |

**Process-action coupling**: P0 fires → drives A0, P1 fires → drives A1.
This creates two independent sense-process-act channels and was the architectural key
for anticipatory behavior in Exp 3.

## Next Experiment: Exp 7 — UCF Gated Floor

**File**: `experiments/exp7_ucf_gated.py`
**Status**: Pre-registered, ready to run

**Pre-registered hypothesis**:
Gate window of 500 ticks is aggressive enough to exclude passive floor riders, but
reproduction under high drain pressure is hard enough that we'll see a genuine Penumbra
population — agents caught between participation and exclusion. Prediction: 10-25% of
population in Penumbra state at peak stress. Collapse delayed vs Exp 6 (>7,410 ticks).
Whether it beats Exp 5 baseline (10,039) is the real question.

Gaming behavior (reproduce-at-minimum-frequency) may emerge as a distinct
Penumbra-adjacent strategy.

**Baseline comparisons**:
- Exp 5 (no floor, drain=1.5): collapsed tick 10,039
- Exp 6 (unconditional floor, drain=1.5): collapsed tick 7,410 (WORSE)
- Exp 7 target: beat 7,410 — ideally beat 10,039

**Parameters changed from Exp 6**:
```python
UCF_GATE_WINDOW = 500      # Must have reproduced within last 500 ticks to qualify
UCF_GRACE_PERIOD = 300     # After gate expires: 300 ticks of 50% support (Penumbra)
UCF_GRACE_INJECTION = 2    # Half of full injection during grace period
```

**Agent states tracked**:
- ACTIVE — reproduced within gate window, full floor support
- PENUMBRA — gate expired, within grace period, 50% support
- EXCLUDED — grace period expired, no support
- Plus existing: DEFENDER, PARASITE, TOXIN, APEX, NAKED

**How to run**:
```bash
cd ~/ai-stack
source venv/bin/activate
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=1 \
  python3 projects/alife/experiments/exp7_ucf_gated.py
```

**What to record**:
- Collapse tick (or survival if it runs to completion)
- Peak Penumbra % (does it hit the 10-25% prediction?)
- Gamer behavior detection (reproduction interval variance per lineage)
- Whether gated UCF + Astris decay reaches stable equilibrium

### Standard Run Pattern

```bash
cd ~/ai-stack
source venv/bin/activate
python3 projects/alife/experiments/exp<N>_<name>.py 2>&1 | tee projects/alife/results/exp<N>_run_$(date +%Y%m%d).log
```

### After a Run

1. Save result JSON to `projects/alife/results/experiment_<N>/`
2. Write analysis report (use the exp 3-5 reports as the template — be precise, honest about failures)
3. Update `docs/alife/EXPERIMENT_STATUS.md`
4. Update the Constella constitutional mapping if the result has governance implications
5. Commit with a descriptive message

### On gen8 vs faithhvm

The sim runs on **faithhvm** (the code is there). Gen8 is used for:
- ChromaDB storage (faithh_observer.py writes lineage data there)
- Always-on background tasks

If you want to run the sim on gen8 for always-on operation, rsync the projects/alife/
directory there and adjust ChromaDB connection config.

## Phase 2 Gate (TempleOS/QEMU)

Phase 2 is a port of the core loop to HolyC in QEMU. The gate conditions are:

1. **Science signal lock**: 3+ consecutive runs show stable, interpretable selection metrics
2. **Causal contrast lock**: Symmetric vs asymmetric information experiments show reproducible effect direction across seeds
3. **Observer lock**: `alife_lineage` schema stable across reruns (no ID collisions, data loss)
4. **Portability slice defined**: One minimal HolyC target loop specified with explicit "what is deferred" list

**Current status (2026-05-18)**:
